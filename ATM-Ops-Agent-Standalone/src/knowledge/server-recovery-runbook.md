# 服务器恢复文档整理版

更新时间：2026-04-30

说明：
- 这份整理版来自用户提供的《服务器恢复文档.pdf》。
- 只保留恢复流程、检查项和命令，不固化密码、导入文件包等敏感信息。
- 凭据应继续放在外部密码本、堡垒机或运行时密钥管理中。

## 适用范围

- FinalShell 导入后的服务器接管
- Web 大屏与系统登录页恢复
- Spark Master / Worker 恢复
- 服务器断网、断电后的人工恢复

## 服务器角色

- `atm-web-server-01` / `atm-web-server-02`
  用于大屏和系统登录页恢复。
- `atm-data-computing-01` / `atm-data-computing-02` / `atm-data-computing-03`
  用于 Spark 主从恢复和状态核验。

## 准备工作

1. 安装 FinalShell 并导入服务器连接信息。
2. 确认凭据来源可用，不在脚本和知识库中写死密码。
3. 先判断故障范围：
   - 仅 Web 页面打不开
   - Spark 页面异常或主节点未选举
   - 机器断网、断电后整体恢复

## Web 恢复

适用现象：
- 大屏无法访问
- 系统登录页无法访问
- 页面空白或加载异常

优先检查的服务器：
- `web1`
- `web2`

常见原因：
- 服务器断网
- 服务器断电
- 服务未正常启动

建议流程：
1. 登录 `web-1` 服务器。
2. 进入系统既有恢复脚本目录。
3. 依次执行既定恢复命令或启动脚本。
4. 观察终端是否有明显报错。
5. 再次打开大屏和登录页验证。

验证清单：
- 页面可以正常打开。
- 登录页面可以正常加载。
- 大屏数据可以正常展示。
- 页面无明显报错或空白。

## Spark 恢复

适用现象：
- `data1`、`data2`、`data3` 任意机器断网或断电后需要恢复
- Spark 服务异常
- 主节点未选举
- Worker 状态异常
- Web 页面状态不正常

### 快速恢复入口

如果需要先做整体拉起，可先执行：

```bash
cd /data
sh start_atm_all.sh
```

### Master 恢复步骤

按顺序在每台机器上处理：
1. 登录 `data1`
2. 登录 `data2`
3. 登录 `data3`

建议执行：

```bash
su root
cd /data/spark/sbin
sh start_master.sh
```

网页端核验：
- 打开 `18080` 端口相关页面
- 确认 `data1/data2/data3` 中已经选举出一个主节点
- 主节点状态正常
- 页面可以刷新，没有明显告警

### Worker 恢复步骤

在确认 Master 已完成选举后，再按顺序处理 Worker：

```bash
su root
cd /data/spark/sbin
sh stop_master.sh
sh stop_workers.sh
sh start_worker.sh
```

说明：
- 文档原意强调脚本在每台机器上依次执行，不要并发混跑。
- 建议顺序仍为 `data1 -> data2 -> data3`。

网页端核验：
- Worker 状态显示为 `ALIVE`
- Worker 数量符合预期
- CPU、内存等资源展示正常
- 页面无明显异常报错

## 验证清单

通用验证：
- SSH 可正常登录
- 关键脚本返回码正常
- 页面能正常打开
- 无持续性报错

Web 验证：
- 大屏可访问
- 登录页可访问
- 页面数据正常

Spark 验证：
- Master 已选举
- Worker 全部 `ALIVE`
- 资源视图正常

## 注意事项

- 恢复类动作属于变更操作，默认应先生成预案再执行。
- 如果是跨多台机器的恢复，推荐按顺序单机执行，避免把集群状态进一步打乱。
- 凭据只通过安全方式注入，不应保存在知识库、技能模板或前端页面中。
